== Purpose of the Plugin

`Octopus Build Integration Gradle Plugin` adds the ability to export the list of components your project depends on into a file,
with only direct (non-transitive) dependencies being considered.

The list is formed based on:

* explicitly defined components;
* Gradle dependencies.

== Applying the Plugin

To use the `Octopus Build Integration Gradle Plugin` in a project, follow these steps:

1. Define the plugin version in `gradle.properties` using the parameter `octopus-build-integration.version`.
2. Apply the plugin in `settings.gradle(.kts)`, as well as in the `build.gradle(.kts)` file of the required module

[IMPORTANT]
====
It is very important to use the **exact version parameter name**:
`octopus-build-integration.version`.

This allows TeamCity to automatically supply the current plugin version
for each build.
====

=== Kotlin DSL

.settings.gradle.kts
[source,kotlin]
----
pluginManagement {
    plugins {
        id("org.octopusden.octopus-build-integration") version extra["octopus-build-integration.version"] as String
    }
}
----

.build.gradle.kts
[source,kotlin]
----
plugins {
    id("org.octopusden.octopus-build-integration")
}
----

=== Groovy DSL

.settings.gradle
[source,groovy]
----
pluginManagement {
    plugins {
        id 'org.octopusden.octopus-build-integration' version (settings.ext['octopus-build-integration.version'] as String)
    }
}
----

.build.gradle
[source,groovy]
----
plugins {
    id 'org.octopusden.octopus-build-integration'
}
----

== Plugin Configuration
=== DSL Reference
[cols="3,6,3,3", options="header"]
|===
| DSL Element
| Description
| Default
| Override via `-P`

| `releaseDependencies { component ... }`
| Explicitly declared components (see the forms below).
| -
| -

| `scan.enabled`
| Enables or disables Gradle dependency scanning. Declaring a `scan { }` block enables scanning implicitly; this flag (or the `-P` override) can still force it off.
| false (true once a `scan { }` block is declared)
| `-Pdependencies.scan.enabled`

| `scan.componentsRegistryUrl`
| URL of the Components Registry service. Used only when scanning is enabled.
| -
| env `COMPONENT_REGISTRY_SERVICE_URL`

| `scan.projects`
| Regular expression used to filter projects by their path
| .+
| `-Pdependencies.scan.projects`

| `scan.configurations`
| Regular expression used to select Gradle configurations from which dependencies are extracted.
| runtime.+
| `-Pdependencies.scan.configurations`

| `outputFile`
| Name of the file to which the plugin will write the resulting dependency list.
| components-dependencies.json
| `-Pdependencies.outputFile`

|===

=== Configuring

All configuration lives under the `releaseManagement` extension. Explicit components are
declared in a `releaseDependencies { }` block and scanning is configured in a sibling
`scan { }` block.

If you want to explicitly add a component, it can be done as follows (no import required):

.build.gradle.kts
[source,kotlin]
----
releaseManagement {
    releaseDependencies {
        component("component_a", "1.0.0")
        component("component_b:1.1.0")
    }
}
----

.build.gradle
[source,groovy]
----
releaseManagement {
    releaseDependencies {
        component name: 'component_a', version: '1.0.0'
        component 'component_b:1.1.0'
    }
}
----

A component can be declared in either form:

* `component name: "<name>", version: "<version>"` (Groovy named arguments);
* `component "<name>:<version>"` (single string);
* `component("<name>", "<version>")` (convenient for the Kotlin DSL).

If you need to include Gradle dependencies, you can configure scanning as follows:

.build.gradle.kts
[source,kotlin]
----
releaseManagement {
    scan {
        // only root project ":"
        projects.set("^:$")

        // only subproject ":service-a"
        projects.set(".*:service-a")

        // subprojects ":service-a" and ":service-b"
        projects.set(".*:(service-a|service-b)")

        // exclude subprojects with names starting with "legacy-"
        projects.set("^(?!.*:legacy-).+")
    }
}
----

.build.gradle
[source,groovy]
----
releaseManagement {
    scan {
        // only root project ":"
        projects.set('^:$')

        // only subproject ":service-a"
        projects.set('.*:service-a')

        // subprojects ":service-a" and ":service-b"
        projects.set('.*:(service-a|service-b)')

         // exclude subprojects with names starting with "legacy-"
        projects.set('^(?!.*:legacy-).+')
    }
}
----

If you need to filter Gradle configurations from which dependencies are collected, you can configure them as follows:

.build.gradle.kts
[source,kotlin]
----
releaseManagement {
    scan {
        // include runtimeClasspath and compileClasspath dependencies
        configurations.set("(runtimeClasspath|compileClasspath)")

        // exclude test dependencies
        configurations.set("^(?!test).*")
    }
}
----

.build.gradle
[source,groovy]
----
releaseManagement {
    scan {
        // include runtimeClasspath and compileClasspath dependencies
        configurations.set('(runtimeClasspath|compileClasspath)')

        // exclude test dependencies
        configurations.set('^(?!test).*')
    }
}
----
